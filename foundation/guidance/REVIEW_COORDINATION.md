# Independent review coordination

The main coordinator assigns one fresh reviewer directly, with no conversation history or author transcript. The user’s selected model and effort apply; record actual exposed provenance once. Workers cannot delegate. A native visible reviewer is the default. Use the native adapter for [Codex](HOST_CODEX.md) or [Claude Code](HOST_CLAUDE.md). The public CLI fallback is Codex-only and available only when explicitly needed/authorized and requires the recipient’s own CLI configuration.

The author completes the whole requested scope and `review-handoff PACK` before dispatch. Send only `packs/PACK/review/handoff.md`, its immutable version, scope and applicable constraints. The handoff routes to original sources, current evidence, coverage, entries and exact records. Keep full drafts, support and findings on disk. Routing snapshots and change reports never grant approval.

Read the original requirements, then the complete bounded `review-view`: follow every `next_start`. Every current teaching record and assessment/card field must be inspected; bounded means chunked, not sampled. Source/page access and independent textbook searches remain available beyond selected quotations. Assess source support separately from complete-wording coverage, explanatory depth and educational quality. Judge the guide independently of practice/cards and the author’s coverage checklist. Review selection flags and claim exemptions substantively within that same pass. Original figure inspection remains required when a visual supports teaching.

Inspect author-supported entries and their completed applications together where practical. Exact entry dependencies come from `entry-inputs`. Write independent receipts only after actual judgments; then `review-request` writes exact current pack inputs and unset decision fields. Copy mechanical bindings locally by code. Complete the required chapter/component judgments, actual page/search records and all four verdicts using [FORMAT](../library/FORMAT.md). Scripts cannot approve, infer acceptance from output existence or update a receipt after an unreviewed change.

Batch actionable corrections in `review/findings.md`, with handoff version, affected record/component, source context and the substantive defect. Use concise actual rationale rather than repeated generic pass text. Keep unresolved findings explicit. Notify the coordinator early for a blocker that invalidates ongoing work; otherwise return one completed result. The main coordinator waits for completion/attention events rather than repeated status/file polling.

For revisions use `review-changes` and continue the same reviewer’s independent context. Recheck all affected dependencies, coverage, explanations and downstream applications. A targeted accepted-baseline review requires its immutable accepted completion snapshot, explicit retained records and current complete-wording/depth assessment. Unaccepted drafts cannot donate judgments. A missing, invalid or stale receipt blocks publication.

Optional Codex-only CLI fallback: `python pipeline.py review-run PACK --model MODEL --effort EFFORT`. Use `--dry-run` for its exact assignment, `--resume` for that reviewer’s recorded session and `--validate-only` for existing receipts. `--force` recovers locks only when recorded owners are stopped; uncertain liveness remains blocked. The CLI uses workspace-write sandboxing and no Git requirement. It does not choose models, create approvals on behalf of a reviewer or replace a live worker. In the native route, delivery follows accepted review in its own fresh coordinator.
