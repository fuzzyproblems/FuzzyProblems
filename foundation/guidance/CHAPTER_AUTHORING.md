# Author and review a chapter

Follow the canonical [specification](../SPECIFICATION.md), especially SG-007–013, SG-023–031 and SG-033. This is a practical route, not a separate standard.

1. Record the current request's scope and exact registered objectives. A full lesson includes all original objectives. Allocate a dedicated chapter to each; keep complete original wording and labels visible.
2. Develop each objective's source-tested component/depth contract in the existing `coverage.json` fields ([FORMAT](../library/FORMAT.md)). During ordinary source reading, interpret every clause, verb and qualifier at the curriculum's learner level; revise provisional components as needed. Before compressing prose, make each `completion_test` briefly identify the essential meanings, distinctions and relationships needed within that component's scope, so mentioning them cannot be mistaken for teaching them. Derive tests from the objective and sources, not retrospectively from what the draft includes. Keep prerequisites, depth, guide-block/evidence mappings and gaps in their existing fields; no new fields, separate plan, glossary or fact-by-fact record is needed.
3. Check valid evidence dependencies and read bounded supplied-textbook passages and continuations. Use context already read to retain required general principles as well as specialised examples; make a targeted additional textbook lookup when a substantive gap needs resolving, including beyond selected entries. During that reading, consider figures for objective-relevant spatial relationships, appearances, processes or comparisons; inspect promising original figures and their captions, never inferring visual content from extracted text alone. Prefer pages already consulted and search further only for a substantive unmet visual teaching need. Do not add source counts, image quotas or another research sweep. Bind added teaching to supplied-textbook support through the existing evidence, citation and review fields. Carry material source qualifications into every artifact under SG-031, including standalone assessment/cards; record conflicts and source gaps rather than inventing content or importing external guidance.
4. Start each independently readable chapter with the short textbook-supported meanings and relationships needed to understand its main explanation. Explain other unfamiliar terms before relying on them; expanding an acronym alone may be insufficient. Keep these explanations in the existing coverage/prerequisite fields with full claims, citations and evidence, using the same research/review pass. Preserve main-topic depth; no glossary, introductory length target or per-term audit. Write the chapter against those tests using the teaching and scope rules in SG-024–026; preserve unique necessary explanations when editing for concision. Include useful inspected figures through the existing source-bound [figure mechanism](../library/FORMAT.md), with captions explaining what the learner should notice. Choose figures from the current objective and inspected source; do not decorate every chapter. Construct the declared practice types from the same evidence under [PDF intake](PDF_INTAKE.md). Essays, calculations, data interpretation and practical scenarios use the existing constructed-response fields and full claim/marking/review rules. For SAQ/SBA: test the intended distinction with defensible SBA competitors and prompt-aligned SAQ marking. Use the existing `marking_points` and `explanation` fields as defined in FORMAT for mark allocation, required components and alternatives. Apply the continuing-card ID convention in SG-033 through existing fields. New packs declare `claim_binding` in their prepared `scope.json`, so tile each record's teaching text with `claims` units and bind every factual unit to the exact quoted passage that supports it, or declare an explicit exemption ([FORMAT "Claim bindings"](../library/FORMAT.md)); the structural gate will not build while a teaching unit is undeclared or bound to a passage that is not quoted for that record.
   Author with local variables/helpers for reusable exact quotations and expand repeated claim/support fields by code. Keep the existing serialized contract; do not ask the model to reproduce the same long quotation in each JSON location. Copy only the selected passage, retaining claim-specific associations and necessary qualifications.
5. Obtain fresh independent review using the user's selected model/effort (SG-004) through a visible native agent by default, with one completed versioned `review-handoff` bundle and original-source access. Follow [bounded coordination](REVIEW_COORDINATION.md) for the single assignment and consolidated findings, and the [existing educational receipt instructions](../library/FORMAT.md#independent-educational-receipts) for component judgments under SG-027–031. Within that review, assess whether the chosen representation teaches the material adequately and correct visual omissions that materially weaken the explanation; text-only chapters are acceptable when text/tables suffice. Resolve substantive findings through that route and bind the exact receipt; stop when substantive and existing acceptance requirements are met.
6. Use [LEARNER_EXPORT.md](LEARNER_EXPORT.md). Verify every objective page, source link, practice/card artifact and evidence occurrence. Record accurate completion and actual checks. Reuse unchanged dependencies and rebuild affected files only; CSS/formatting-only repairs retain factual approval. Apply the desktop-only, exception-based presentation policy in SG-032; use output screenshots only where they help resolve a real concern. This does not restrict inspecting or including useful original source figures.
