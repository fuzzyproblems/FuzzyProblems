# Start a task

1. Read `AGENTS.md`. For installation or tooling, use [SETUP](foundation/guidance/SETUP.md); use `$fuzzy-start` in Codex or `/fuzzy-start` in Claude Code, or run `pipeline.py init --host codex` / `pipeline.py init --host claude` with Python 3.12. No input documents or Git repository are needed. Reruns preserve existing documents, configuration and work.
2. Ask the user to supply PDFs in `Objectives/`, `Textbooks/` and optionally `PastPapers/`. Establish learner level, unit grouping and requested scope. Existing files can answer these questions; ask only for missing material decisions. A full lesson means every original objective. Non-numbered goals receive stable intelligible numerical labels while retaining original labels.
3. Use [PDF intake](foundation/guidance/PDF_INTAKE.md): discover inputs once, inspect original source identity and representative extraction quality, register complete source-anchored units, and record observed assessment style if supplied. Scripts produce no educational approval. Keep source gaps explicit.
4. For production read the selected host’s job-queue skill, its default route and host adapter. Assigned workers instead read only their role and its references. Check exposed author/reviewer model and effort once; inherit the selected pair. Read `pipeline-config.json` through `pipeline.py host --host HOST` for host-specific delivery settings. Claude defaults to session inheritance; Codex preserves its configured delivery pair. If the host cannot provide independent fresh workers or the configured model, ask for an available configuration or use the explicitly authorized Codex CLI fallback when working in Codex; never silently use the author as reviewer.
5. Prepare the requested pack, ask for or honor delegated Anki tags, research and author, obtain independent review, resolve findings, then build/check/publish. Follow [WORKFLOW](foundation/guidance/WORKFLOW.md) and [RUNBOOK](RUNBOOK.md). The first complete real lesson must pass before bulk production.

Continue jobs from their internal pack checkpoints. No approvals exist by default. Do not infer completion from an empty registry, source check, render or valid schema. Current source and semantic dependencies control reuse.

For separately published objectives of one lesson, use one lesson collection with versioned objective subfolders when appropriate. Pass the same destination to `python pipeline.py build PACK --folder Example-Lesson/Objective-1-v1` and `publish PACK --folder Example-Lesson/Objective-1-v1`. Unconfigured packs retain flat publication. Root `StudyGuide.html` and nested `navigation.html` pages refresh after publication; a valid sole `Objective N · topic` chapter opens directly, including earlier versions. After manual folder changes, run `python regenerate_study_guide.py` or `python pipeline.py catalogue`. Changing a delivery's depth requires a new checked export with corrected textbook links; catalogue refresh alone cannot repair them. See [RUNBOOK](RUNBOOK.md) and [learner export](foundation/guidance/LEARNER_EXPORT.md).
